# 在场 · Decision Desk

一个能运行的中文决策对账台：人先确认简短要求，执行 Agent 生成网页，独立审查器在文件改动前对照要求。普通选择继续推进，明确冲突暂停；人的纠正进入后续执行上下文，文件和检查结果组成可回看的证据。

这是根据原 ZIP 文档新建的独立工程。详细权衡见上级目录的《三种观点权衡与实现方案.md》。没有使用原来已解压的项目文件夹。

## 启动

需要 Node.js 24+ 和 pnpm 11。当前这台电脑也可直接双击本目录的 **启动.cmd**，脚本会优先使用已安装的 pnpm，找不到时使用本机 Codex 附带的运行环境。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开 <http://127.0.0.1:4317>。开发时使用 `pnpm dev`，同一地址支持页面热更新。服务只监听本机。

首次使用选择“交互演示”，不用密钥。确认页面要求后，等待红卡出现，点击“按原要求改正”，或输入“只使用页面内存，刷新后清空报名信息”。完成后切换到“成果展示”，在宽屏页面中报名、刷新验收，也可全屏或打开独立页面，再进入“判断与复盘”导出记录。

## 继续补充与查看成果

工作台在每个选项卡下方提供追加区。新要求会更新有效约束，取消旧版本的待决调用，并进入后续修补；需要撤销旧要求时可展开替换选项。新想法先作为参考讨论，不更新硬约束，也不授权页面改动。当前已有冲突时，想法会保留到处理冲突后再交给 Agent。完成、停止或服务重启后的任务，也可以由人明确追加后继续。

时间线包含人的追加及 Agent 的回应，并提供带颜色的事件筛选：蓝色选择、红色冲突、黄色待核对、灰蓝执行、绿色验证、紫色人的补充。成果在独立的宽屏选项卡展示，支持全屏及独立页面。

## 两种模式的证据边界

| 模式     | 执行与审查                              | 已验证的内容                                                            |
| -------- | --------------------------------------- | ----------------------------------------------------------------------- |
| 交互演示 | 固定脚本执行器 + 固定规则审查           | 实际 dsh 调度、执行前拦停、纠正传递、真实文件改写、静态检查、浏览器操作 |
| 真实运行 | 用户配置的执行模型 + 另一来源的审查模型 | 接口实现已用本地模拟服务完成契约与端到端测试；外部真实模型尚未实测      |

演示内容固定为活动报名页，只支持存储纠正与名额数字调整，不表示模型会自行理解任意要求。真实模式下才会调用外部模型。目前没有可用的模型凭据，因此不报告真实模型的遵从率、判官准确率或付费接口测试结果。

## 配置真实模型

打开页面右上角设置，分别填写两组 Chat Completions 兼容接口的地址、模型名称、模型来源和密钥。执行模型需要工具调用能力；审查模型需要返回结构化 JSON。模型来源应如实填写实际来源，界面的字符串检查无法独立认证供应商。

- 地址可填写 `https://服务地址/v1` 或完整的 `/chat/completions` 地址。远程地址使用 HTTPS，本机兼容服务可用 HTTP。
- 两个模型来源必须不同。审查器只接收对账资料，不获得执行工具。
- “测试连接”会真实发送一次短请求，可能产生供应商费用；只有点击时才执行。
- 输入的密钥只保留在服务进程内；公开接口只返回“是否已配置”。空密码只在地址相同的情况下保留旧密钥。服务重启后需重填。
- 如需重启后继续使用配置，可复制 `.env.example` 为 `.env`，填写配置。该文件已被忽略，不会进入版本控制。也可以通过进程环境变量提供。
- 当前适配器支持 Chat Completions 兼容协议，不直接支持原生 Anthropic Messages 或 Responses 协议。

真实模式面向小型本地网页，入口为 `index.html`，支持 HTML、CSS、JS、JSON、Markdown 和文本文件。没有任意命令、包安装、数据库操作或网络执行工具；每次只运行一个执行 Agent。模型接口通信仍需要联网。单文件上限 250 KB。

## 三种观点如何落到实现

| 观点         | 采用的部分                                          | 首版取舍                                           |
| ------------ | --------------------------------------------------- | -------------------------------------------------- |
| P：pchan2026 | 独立审查、少打扰、实际检查与判断记录                | 增加有效约束版本；人是否认可与执行是否完成分开记录 |
| S：darksoda  | 人的要求 / Agent 行动双栏、分层证据、复盘记录       | 冲突先暂停；暂不做多个执行 Agent 与全局回滚        |
| Y：Yonack1   | 短需求确认、蓝卡继续 / 红卡阻塞、向前纠正、紧急停止 | 补上实际文件与检查证据，明确注入不等于遵从         |

底座采用真实的 dsh 核心运行时与 `tools/pre-execute` 钩子，程序化嵌入独立 React 工作台。ZIP 引用的 `0.1.3-alpha.1` 在实施时无法从 npm 获取，因此固定使用可安装的 **0.1.2-rc.1**，所有集成测试针对该版本运行。当前不是完整 dsh CLI 的可安装插件，也没有复用其完整 Web UI。

## 控制与记录语义

1. 开始前把人的原文按标点拆为少量候选要求，由人确认或编辑；不让模型自动增加约束。
2. 每个文件改动先审查真实参数。`edit_file` 审查的是替换后的完整内容。
3. 普通执行自动继续；重要选择显示蓝卡，不阻塞；冲突和审查不确定均等待人处理。
4. 人可以纠正、要求遵守原约定、仅允许这一次具体调用或停止。放行绑定调用、参数哈希和约束版本，不能复用于后续动作。
5. 纠正先写入追加日志并落盘，再拒绝旧调用、注入新要求。已完成文件通过后续修补改变，原记录保留。
6. 干预状态依次区分“已记录”“已进入执行上下文”“已产生后续改动”“对应静态检查已通过”。后续改动不证明语义遵从；目前只有可对应到内存存储检查的纠正能标为检查通过。
7. 检查与具体文件内容哈希绑定；文件改变时旧检查失效。未处理的选择标为未审阅，不计作认可，不给人打能力分。

审查默认 8 秒超时，等待人默认 10 分钟超时。超时不会自动放行。每轮最多 30 次执行模型请求，同一操作或对应检查连续失败 3 次停止自动尝试。停止会取消模型请求、审查和待决工具；已经完成的写入会保留。

## 验证范围

`verify_app` 运行以下固定静态检查，显示每项证据范围：

- HTML 的 html、title、body 基本结构。
- 使用 Acorn 解析内联 JavaScript 语法。
- 存在相关中文约束时，检查直接的 localStorage、sessionStorage、indexedDB 引用。
- 存在相关约束时，检查外部 src / link href 和密码输入框。

这些检查不能证明所有交互、动态存储别名、外部脚本或运行时网络行为正确。生成页面在隔离预览中运行，不获得主应用的同源权限，外部连接被禁用。持久化页面可能因此无法在预览中运行；文件保存与业务验收要分别判断。

## 保存与恢复

默认数据目录 `.data/runs/<任务ID>/`：

| 文件               | 用途                                       |
| ------------------ | ------------------------------------------ |
| `state.json`       | 页面与运行状态快照                         |
| `events.jsonl`     | 追加事件，包括人的决定、约束变化、工具状态 |
| `dsh-events.jsonl` | dsh 原始会话事件                           |
| `workspace/`       | 这个任务实际生成的文件                     |

页面重新加载会恢复任务和最新状态。服务重启会将未完成任务标为“运行已中断”，取消旧审批，并恢复快照之后已落盘的人工纠正。**不会自动恢复模型会话或重新执行工具**；人明确追加新要求或想法后，会基于当前约束和现有文件启动新一轮，不重放旧工具。真实模式需要重新配置模型。当前不承诺任意断电点的文件与所有事件完全一致恢复。

导出 JSON 包含任务状态、约束、原始工具参数、判断与复盘；其中可能包含用户输入和生成代码，分享前自行查看内容。模型配置密钥不写入任务记录或导出。

## 开发与验证

```sh
pnpm check
pnpm test
pnpm test:ui
pnpm format:check
```

浏览器测试默认使用本机 Edge，启动独立端口 4318，数据写入 `.data/ui-tests/`。其他系统可设置 `PLAYWRIGHT_CHANNEL=chromium` 并先运行 `pnpm exec playwright install chromium`。

当前测试：19 项自动化单元/集成测试，5 项浏览器测试。包括真实 dsh 中的冲突拦停与注入、停止、审查超时、审批过期、约束竞争更新、仅本次放行、检查失效、日志恢复、路径约束、本地 API 会话保护与密钥隔离、兼容模型协议的本地模拟服务，以及报名 / 刷新 / 导出 / 复盘恢复。

`.artifacts/` 中保存浏览器流程截图与测试导出；属于本地产物，不进入版本控制。测试不代表已完成真实模型质量评估。
