## 已定决策

### D1 · 大方向（新框架，2026-09-04 darksoda 提出）

- 核心对象是一份**工作流程分步记录**：每一步记录「人类说了什么」＋「agent 实际做了什么」两栏。
- 记录这件事**交给异源 AI**（非干活模型本身）来做——与调研结论一致（自报不可靠，HiL-Bench 实锤；对应旧 D6 判官思路，但明确要求异源）。
- 人类基于记录可以**指示修改特定部分**。
- 拍板：darksoda，2026-09-04。

### D2 · 定点修改的生效方式：回滚重做 + 原分支暂存

- 人类指着某一步要求修改时：**回滚到该步重做**，但**原分支暂存**（不作废、不删除），留作记录和 redo 的依据。
- 即 rewind-and-fork 路线，但旧时间线完整保留——回应了"回滚丢下游工作"的硬伤（工作在暂存分支里没丢）。
- 已接受的代价（拷问时明示）：与调研主推的"只向前生效"差异点相反，走的是 LangGraph time-travel 同族路线，差异化要另找（旧时间线可对比/可 redo 或是切入点）；外部副作用（已发的邮件、已跑的命令）仍然收不回，需在演示与说明里避开或明示。
- 拍板：darksoda，2026-09-04。

### D3 · 记录粒度：分层，粗粒度展示、细粒度可展开

- 默认展示粗粒度（语义级步骤），每步可展开看细粒度（具体的文件改动/命令等动作）。
- 规避两头风险：不刷屏（审批疲劳失败案例），又保留细回滚点。
- 拍板：darksoda，2026-09-04。
- 待细化：粗粒度由谁划分（大概率异源记录员断句）。

### D4 · 异源记录员职责：对账员（标记不拦截）

- 记录员除转写两栏外，负责**对账**：标出「agent 自己拍板（人没指定）」和「与人类指令不符」的部分。
- **不打断干活**——非阻塞浮出，人事后看到标记可用 D2 的回滚重做处理。与三档审批文献的 Tier 2（notify 非阻塞）一致，规避审批疲劳。
- 已接受的代价：冲突人类明确指令的动作也不会被实时拦停，发现时可能已多跑几步（有 D2 兜底，成本可控）。
- 拍板：darksoda，2026-09-04。

### D5 · 证明层：时间线可回放 + 一页报告摘要，两个都要

- 回应赛题第二层「人变强/被证明」（出题人原话：它才是出这道题的原因）。
- **时间线可回放**：双栏记录 + 对账标记 + 回滚/重做历史，本身就是过程证明。
- **一页报告摘要**：会话结束由异源记录员自动汇总——人下了哪些指令、agent 自己拍了几个板、人几次指出偏差并回滚拧回方向。
- 归因口径沿用调研结论：归因人的判断，不归因代码行（避开 Cursor Blame/git-ai 已做死的行级归因，也避开与出题方"过程即作品集"撞车）。
- 拍板：darksoda，2026-09-04。

### D6 · 实做范围：单人多 agent

- 一个人指挥多个 agent，**所有 agent 的动作并进同一条时间线**，由异源对账员统一对账。
- 接上多 agent 决策信息孤岛痛点（中文社区实锤）；对账员可标出 agent 间互相冲突的动作。
- 与纯编排类产品（Vibe Kanban 等，红灯区）的区别：不做任务分发/编排，只做记录与对账——立足点仍是「人看得懂、管得住」。
- 已接受的代价：比单 agent 明显更重，demo 复杂度上升。
- 拍板：darksoda，2026-09-04。

### D7 · 技术路线：拿 dsh（DeepSeek Harness）改

- 基于 DeepSeek 官方开源的 agent harness **dsh**（github.com/deepseek-ai/deepseek-harness，2026-08-13 随 V4-Pro 开源，"Everything is a Plugin" 架构，developer preview）做二次开发，不绑 Claude 生态。
- 拍板：darksoda，2026-09-04。
- **核查结果（2026-09-04 已回，绿灯）**：四项能力核查见 docs/research-2-raw/05-dsh-feasibility-S.md。①动作拦截：原生四段 waterfall（pre-execute 可 deny/改写），外部可经 SDK 事件流全量消费 ✅；②上下文注入：`agent.inject()` / `Agent.steer()` / 远程 prompt 入队 ✅；③过程记录：append-only 事件溯源日志，turn/step 天然分层（正好对上 D3 分层），JSONL 落盘 + 自带时间线视图 ✅；④会话 fork 原生支持、原分支血缘留存（正好对上 D2 暂存），**但工作区文件无快照**——需自己监听 turn 结束打 git commit/branch 配合会话 fork（可行性高，是唯一黄线）。异源模型原生多 provider，记录员宜做独立进程直调异源 API。次级风险：developer preview 期 API 漂移，开工即锁定 commit。dsh 侧几乎不用改内核，工程量集中在工作台 UI 与对账逻辑。

### D8 · Demo/路演：现场真跑单 agent 简化版，多 agent 用录屏

- 2 分钟路演动线：现场真跑一个预埋决策点的小任务（单 agent）——时间线上对账标记冒出来 → 人指着一步回滚重做 → 原分支暂存可见 → 弹出报告。
- 多 agent 并线对账（D6 的完整形态）用赛期提前录好的真实操作录屏展示。
- 现场部分另备全程录屏，作网络/模型故障兜底。
- 拍板：darksoda，2026-09-04。

### D9 · 多 agent 回滚语义：全局回滚

- 时间线全局唯一；回滚到某步 = 整个工作区回到那一刻的快照，所有 agent 停下、从那里重来。
- 理由：实现最简单可靠（全局快照链，git 即可）；被牵连的 agent 工作因 D2 原分支暂存并未丢失。
- 已接受的代价：没出错的 agent 也要重跑（时间成本）；按 agent 独立回滚（worktree 隔离）不实做，可进 roadmap。
- 拍板：darksoda，2026-09-04。
- 暂存分支按时间线分（全局快照），不按 agent 分。

### D10 · 异源记录员模型：Day1 实测挑选

- 开赛 Day1 花半天，用同一段干活记录对各家模型（Claude/GPT/Gemini/国内头部，赛事均免费不限量）实测**对账准确率**（能否准确标出 agent 自作主张/违背指令处），择优定为记录员。
- 理由：记录员质量是全方案关键路径（调研实锤：判官质量决定成败），值得半天成本；唯一硬约束是**异源**（非干活模型 DeepSeek 系）。
- 拍板：darksoda，2026-09-04。

## 对齐产出的产品全貌（一段话版）

一个跑在 dsh（DeepSeek Harness）上的**多 agent 过程对账台**：一个人指挥多个 agent 干活，异源 AI 记录员把每一步「人类说了什么 / agent 实际做了什么」记成一条全局时间线（粗粒度展示、细粒度可展开），并对账标出 agent 自作主张、或与人类指令不符的动作——只标记，不打断。人看到不对，指着那一步**全局回滚重做**：整个工作区回到那一刻，原分支自动暂存（留作记录与 redo 依据）。会话结束自动产出两样东西：可回放的时间线 + 一页报告摘要（人下了哪些指令、agent 自己拍了几个板、人几次拧回方向）——归因人的判断，不归因代码行。路演现场真跑单 agent 简化版，多 agent 形态用赛期真实录屏。
