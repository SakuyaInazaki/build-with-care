# 01 · CHAPTER ONE　什么是命题挑战组？

一句话：有人出题，你来解决。

命题挑战组和开放创新组的区别在于——开放创新组由你自己定义问题、自己定义方向；命题挑战组有出题方给出的具体场景和命题方向，你的作品需要回应这个场景。但两条赛道最终的要求相同：把想法做成真正落地的作品。

# 02 · CHAPTER TWO　三大赛道

## TRACK THREE · 赛道三　给 Multi-Agent 时代，造一个人还在场的工作台

### 出题人 · QUESTION SETTER

- **李知非**　CheeseX 创始人，主导开发知是科研平台，吴玉章奖学金、人大“先锋奖章”得主，Princeton CS PhD，参与 GitHub 开源项目累计 Star 30k+

### 赛道说明

微软 CEO Satya Nadella 说他自己同时跑着一百个 Coding Agent，然后他说：“我同时开着一百个 Agent 会话。它们转嫁回给我这个人的认知负担高到不可承受，我现在需要一个新的界面。”

2026 年 AI 领域的竞争焦点，已经从“单个模型有多强”转向怎么编排多个 Agent 协同完成一件复杂的事。这不是大公司才有的问题——9 月 4 日 17:30 之后的两天半，你会亲自经历一遍缩小版：

- 01 让 Agent 写一段，跑起来不对，再让它改，改到第三遍已经看不清它到底动了哪里
- 02 队友在另一台电脑上开着另一个 Agent，改的是同一个文件
- 03 队里学设计、学新闻的同学有很好的想法，但插不上手，只能等着看结果
- 04 第二天下午，没人说得清现在这一版是怎么来的

本赛道的命题：给 Multi-Agent 时代，造一个人还在场的工作台。“人还在场”指两件事：这一刻他管得住 Agent，一年之后他自己也变强了。第二件事没有第一件显眼，但它才是出这道题的原因。

**出题方简介**：知是（CheeseX）是一个面向教育的 Agent 协作平台。每件事开一个话题，话题自带一个隔离沙箱和一个 Claude Code Agent，多条支线并行推进，结论自动汇总；过程一边干一边沉淀成文档，做完之后，这个过程本身就是你的作品集。

### 赛题说明

围绕“人和 Agent 一起把一件事做成”，从 0 到 1 构建一个能跑的东西。形式不限：网页、小程序、命令行工具、浏览器插件、机器人，或者一套跑得通的 Agentic Workflow。唯一的要求是它能跑，并且解决一个你真的遇到过的问题。最好的题目来源就是这两天半的你自己——你和 Agent 协作时最难受的那一刻，几乎肯定也是隔壁桌那支队伍难受的那一刻。

以下四个方向是参考方向，不是限定：

#### 方向一：Human-in-the-loop——让人还看得懂、管得住

Agent 一次改动，产出可能有几百行，你只能大致扫一眼点“同意”。次数一多，你自己都不确定刚才签的字是什么。能不能让人在 30 秒内判断出这次 Agent 做得对不对？

举个例子：做一个改动翻译器——Agent 改完，它用三句话说清楚改了什么、为什么这么改、哪里最可能出错，让不看代码的人也能验收。

#### 方向二：Multi-Agent Orchestration——让多个 Agent 和多个人不打架

三个人各开一个 Agent，改同一个项目，覆盖、冲突、重复劳动都会发生，而且往往几个小时之后才被发现。能不能让多个 Agent 和多个人在同一件事上并行推进，还互相知道对方在干什么？

举个例子：做一个实时分工板——谁在改哪一块、哪个 Agent 正在跑什么，一眼看清；两个人快要动到同一个地方时提前提醒。

#### 方向三：Vibe Coding 的下一步——让不写代码的人也能指挥 Agent

Vibe Coding 让会写代码的人快了十倍，但门槛并没有真的消失：你还是得看得懂它写了什么、跑起来报什么错。黑客松欢迎非技术专业的同学，可现实是不会写代码的人常常只能提想法，动手那一步永远压在队里的技术同学身上。能不能让一个完全不碰代码的人，自己把想法变成能跑的东西？

举个例子：做一个所见即所得的指挥台——用中文描述你想要的界面，Agent 做出来，你在页面上直接圈“这块颜色不对”“这里要能点”，全程不用看一行代码。

#### 方向四：Attribution——让“我做的”和“Agent 做的”分得清

一个人指挥 Agent 做完一个项目，怎么向别人证明他学到了什么？现在的答案是没有答案：说不清，也验不了。能不能让一个人指挥 Agent 做成的事，变成别人信得过的能力证明？

举个例子：做一个贡献可视化工具——项目做完自动分得出哪些是人的决定、人在哪几次把跑偏的方向拧了回来、哪些是 Agent 自己跑完的，一眼看出这个人到底在里面干了什么。

### 这道题的边界

把人从你的作品里拿掉，它就不该还能正常工作。一条全自动跑完、不需要人看一眼的 Agent 流水线，不是这道题的作品，那是开放创新组的地盘。本赛道要的是人和 Agent 之间的那一层：人在哪里看、在哪里拍板、在哪里被证明。

工具是自由的，命题不是——用什么语言、什么框架、在谁的平台上写，完全随你；但你交上来的东西得解决“人跟不上 Agent”这个问题的某一面。

### 出题方提供的工具支持

选了这道题，下面几样直接拿去用：

- **最前沿的模型，免费，不限量**　赛事期间可随便调用 Claude、GPT、Gemini 以及国内头部模型，不设额度上限
- **每队一个云端沙箱**　浏览器打开就能写、能跑、能预览，不用在自己电脑上装任何东西
- **一个真能干活的 Agent**　知是内置的 Agent“芝士”，跑在 Claude Code 上，支持 MCP、Skills 和 Subagent 编排
- **赛前就能领，不用先定赛道**　录取后开放注册，可提前摸熟环境；9 月 4 日 Challenge Briefing 之后，选了本赛道的队伍现场配沙箱和额度

不要求你基于知是开发。用什么工具、什么技术栈由你决定，你交上来的作品可以和知是毫无关系。上面这些是给你的资源，不是这道题的前提。

# 04 · CHAPTER FOUR　通用赛事规则

**从 0 到 1，但准备好再出发**

代码在 Hack Start 之后才开始写。但赛前你可以做很多事：观察你选择的场景里最让你或身边同学不爽的是什么、问 5 个同学他们最想要什么样的工具或陪伴、画草图理清核心流程。有准备地出发，比从零开始乱撞强十倍。

**和已有产品重复也没关系**

你的赛道上可能已经有成熟产品或出题方的现有平台。如果你做一个“更好的版本”——欢迎。你的交互设计可能更好，你的匹配逻辑可能更聪明，你的陪伴感可能更真实。我们不怕重复，只怕没有新想法。

**做完比完美重要**

两天半的时间很紧。一个能跑通核心流程的 Demo，胜过十个设计文档。来不及做全部功能？只做核心链路就够了。来不及打磨 UI？用现成组件库。评审看的是“这个东西真的被做出来了”，不是“它符合生产标准”。

# 05 · CHAPTER FIVE　赛后权益

命题挑战组的独特之处在于：出题方是真实的平台或产品团队，优秀方案不止步于路演平台。各赛道出题方将为优秀方案提供不同的后续支持：

- 01 推广资源与技术合作
- 02 真实用户触达渠道
- 03 产品迭代支持
- 04 平台内署名展示

具体支持内容因赛道而异，详见各赛道出题方在赛后的进一步说明。

**知识产权说明**

参赛者拥有作品的知识产权，出题方获得“参考创意进行实现”的授权，并在实现中显著署名。具体条款以双方确认的协议为准。

你的 Hackathon 作品不只是一次比赛的产物——它有可能真实服务数千名同学的校园生活。

# 06 · CHAPTER SIX　作品提交要求

- **Demo**　现场可运行的原型（网页／小程序／命令行工具／插件／任何形式），本地运行即可，不要求部署上线
- **项目说明**　1 页以内：你抓的是哪个问题、为谁解决、怎么解决
- **代码**　可读即可，需要有 README 说明如何运行
- **路演**　2 分钟，讲清楚“我做了个什么，给谁用，解决了什么”

作品 9月6日 12:30 冻结，之后再按抽签顺序路演。

# 07 · CHAPTER SEVEN　FAQ

**Q：命题挑战组和开放创新组有什么区别？**
A：命题挑战组有出题方给出的具体场景和命题方向，你的作品需要回应这个场景；开放创新组由你自己定义问题、自己定义方向。

**Q：我可以同时参加命题挑战组和开放创新组吗？**
A：不可以。每支队伍只能选择一个组别参赛。

**Q：一个队伍只能选一个赛道吗？**
A：是的。每支队伍在命题挑战组内选择一个赛道提交作品。

**Q：三个赛道的评审是分开还是统一？**
A：各赛道分别评审，分别产生奖项。

**Q：不会写代码，能参加赛道三吗？**
A：可以。赛道三的方向三（Vibe Coding 的下一步）正是为降低门槛设计的；出题方提供的云端沙箱也让你不用在自己电脑上装任何东西。

**Q：赛后优秀方案落地，知识产权怎么算？**
A：赛后与出题方单独协商。基本原则是：参赛者拥有作品的知识产权，出题方获得“参考创意进行实现”的授权，并在实现中显著署名。具体条款以双方确认的协议为准。

# ∞ · POSTSCRIPT　最后的话

命题挑战组的三个赛道，最终目标相同：把“要是有一个东西能这样就好了”变成现实。

不需要完美的代码，不需要考虑商业化，不需要符合任何已有平台的设计。只需要你：看到问题 → 动手做 → 做出一个能跑的东西。

两天半很短，但足够把一个念头变成别人能看见、能摸到、能用的东西。
