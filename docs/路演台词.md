## 0:00–0:15 问题

> 你把一句话需求交给 agent，回来是六百行 diff。数据库用什么、要不要登录、目录怎么分，全是它替你定的，你只在写完之后才发现哪个错了。
> Nadella 说他开着一百个 agent 会话，认知负担压回到人身上，需要一个新界面。我们做的就是这个界面：人不审 diff，只审决定。

## 1:30–1:50 报告与「人变强」

> 这份报告不数代码行。它说：这场会话 agent 做了 N 个决定，我判断了 M 次，其中 1 次把方向从 SQLite 拧回 Postgres，1 次它撞墙三次向我求助；一张绿卡带 executor 证据；灰卡只是执行，不算任何人的贡献。
> 赛题说"人还在场"有两层：这一刻管得住，一年后人变强了。第二层看的不是仓库里哪行是你写的，而是这份记录——你在第三张卡上看出了什么。归因人的判断，不归因代码行。

## 1:50–2:00 收尾

> Agent 越快，人越不该看 diff，只该看决定。在场，就是这一秒你能说不，一年后你能证明你说过。谢谢。

## Q&A 备忘（每条 ≤ 30 秒）

**为什么不直接看 diff / 和 CodeRabbit 这类 review 工具有什么区别？**
它们在改动之后翻译 diff，我们在改动之前截住决策点。红卡是在写文件前拦的，SQLite 文件根本没落盘。600 行 diff 压成 5 张卡，绕开人审几百行就失效的问题。

**判官判错了怎么办？**
两种错各有出口：误红（不该拦却拦了）——人点放行，一秒；漏红（该拦却判成蓝）——蓝卡还在侧栏，随时可事后翻案，约束向前生效。判官和记录员独立于干活 agent，卡片写明谁判的、置信度多少；宁可漏也不刷屏是产品选择，审批疲劳比漏判更糟。

**翻案不回滚，那已经做的事怎么办？**
forward-only：红卡在执行前被拦，没有要回滚的东西；蓝卡事后翻案时已完成的工作保留，约束只进未来。rewind-and-fork：从已完成 turn 边界开新分支，原分支暂存可对比。★ 逻辑 fork 不回滚磁盘文件，邮件、网络请求这类外部副作用收不回来，界面上明写着。

**多 agent 怎么办？**
有 multi-agent 场景：3 个 agent 并发，动作并进同一条 append-only 时间线，按 sequence 合并，可按 agent / branch 过滤，报告有 per-agent 统计。我们不做派活和编排，只做记录与对账——立足点仍是人看得懂、管得住。

**需要 DeepSeek Harness 吗？**
不需要。工作台是 harness 无关的本地 HTTP 服务。dsh 是目标底座之一：我们在它源码里跑过 POC，pre-execute 挂起、deny 理由回传、inject 只向前、cancel 叫停都实测通过；★ 仓库里现在只有 adapter 契约和 mock，真实运行时没装，不冒充已接入。

**★ 什么是模拟的？（必须答全）**
三件事。一、台上跑的是服务器驱动的演示剧本，不是模型即兴；配置模型后同一界面切换到真 agent，卡片 provenance 会标 `llm:<model>`。二、没配模型时判官和记录员是规则实现，用来演示职责分离，不代表真实异源模型的准确率。三、执行器只允许小范围本地命令，写文件落在会话独立工作区；dsh、Git 快照回滚、真实异源模型都没接。能跑通的是：红卡 gate、四档裁决、两种纠偏、失败升级、时间线、报告——这些是真实逻辑，有测试覆盖。
