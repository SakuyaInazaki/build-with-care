# 需求对齐记录

> 由需求对齐讨论（grill-me 拷问模式）逐条产生。开始于 2026-09-04。
> 规则：只记讨论里真实定下的决策，AI 不预填内容。推送 GitHub 由 pchan2026 发话，不自动推。

## 总框架（D1 修正版）

**以赛道命题为主，不按"四个方向"做题**（官方明示方向是参考不是限定）。产品要回应的是命题本身：

- 「人还在场」两层：这一刻**管得住** Agent；一年后人**变强了**。
- 赛题边界原文的三个落点：人在哪里**看**、在哪里**拍板**、在哪里**被证明**。

产品 = **决策流**（看 + 拍板：agent 替你做的决定实时浮出，可翻案，翻案只向前生效）+ **会话报告**（被证明：干完自动生成人的判断记录）。四个方向只在路演时做评审视角的映射（约等于方向一+四），不反过来框定产品。

## 已定决策

### D1 · 大方向（修正版）

- 做「决策流」：人只审决定，不审 diff。回应命题的"管得住"。
- 多 agent 编排类能力（方向二）不做，最多进 roadmap 一页。
- 非技术同学可用（卡片为中文判断题）是天然属性，不额外投入开发，路演口头点到。
- 拍板：pchan2026，2026-09-04。修正记录：最初表述为"主攻方向一+四"，pchan2026 纠正为"以赛道要求为主，方向仅供参考"。

### D2 · 贡献证明形态：会话报告

- 每次会话结束自动生成一份报告："agent 做了 N 个决定，你放过 M 个、翻案 K 次、其中 X 次纠正了跑偏的方向"，附每次翻案的前后对比。回应命题的"被证明/人变强"。
- 不做可导出的对外证明、不做跨会话成长档案（后者可作路演"未来形态"一页讲，不实做）。
- 归因口径：**归因人的判断，不归因代码行**（行级归因已有成熟品：Cursor Blame / agentblame / git-ai；亦避免与出题方"过程即作品集"撞车）。
- 拍板：pchan2026，2026-09-04。

### D3 · 卡片体系：分级混合，颜色 = 块的状态，会流转

- 🔵 蓝 = agent 自由发挥拍的板（人没指定），浮出不阻塞，随时可翻案；
- 🟢 绿 = 已跑通/验证过的块；
- 🔴 红 = 出了问题的块；
- ⚪ 灰 = 纯执行，不显示只进日志。
- 颜色随进展流转（蓝 → 绿 / 蓝 → 红）。整体是"状态板"而非"审批队列"，规避审批疲劳失败案例。
- 拍板：pchan2026，2026-09-04。
- 待细化：蓝的判定基线（是否强制 plan 起步，D6 讨论中）。

### D5 · 绿的判定：验证过才绿

- 只有该块对应的验证动作真实通过（测试通过 / 构建成功 / 明确的检查动作成功）才由蓝转绿；未验证的保持蓝。
- "没报错"不算绿——绿必须可信，人才敢安心跳过。
- 拍板：pchan2026，2026-09-04（选项 2）。

### D4 · 红卡分两种，处理方式不同

- **运行报错类**（命令挂、测试失败）：不阻塞，agent 自修；**连续修不好升级为阻塞求助**（自修阈值默认 3 次，可调）。对应调研痛点"agent 不会主动求助/自信失败"。
- **约束冲突类**（要做的事与人定过的计划或翻案过的约束冲突）：**立刻阻塞**等人拍板。
- 拍板：pchan2026，2026-09-04（选项 3）。

### D6 · 蓝卡判定：独立判官 agent，不强制计划

- 判色（蓝/灰/红）由**独立判官 agent** 执行，不靠干活 agent 自报（规避调研实锤的自报不可靠问题）；判官同时生成卡片的人话文案。
- 参照基线 = **对话原文**（人说过的话），**不强制**开工先确认计划（与调研建议不同，pchan2026 拍板）。有计划时判官自然会用上，但不是流程强制。
- 已接受的代价：蓝卡会偏多；判官质量成为关键路径；每个卡点多一次模型调用（赛事模型免费，选快模型）。
- 拍板：pchan2026，2026-09-04。

### D7 · 翻案交互（惯例默认，芝士代定已告知）

- 点开卡片：判官预生成 2-3 个翻案方向供一点即选 + 自由文本输入框，可只点选项、可补充细说。
- 翻案生效方式沿用方案核心：作为约束注入，只影响后续，不回滚已完成工作。

### D8 · Demo 剧本：预设小项目，现场真跑

- 准备一个可控小任务（预埋必出的决策点，如数据存储选型、要不要登录、框架选择），路演现场让 agent 真跑：卡片真冒、人真翻案、agent 真改向。
- 翻案剧情提前彩排；录屏作现场网络/模型故障的兜底。
- 拍板：pchan2026，2026-09-04（选项 2，纯现场版，不做狗粮实录页）。

## 对齐产出的产品全貌（一段话版）

一个监督面板 + 判官机制：干活 agent 每到卡点（写文件/跑命令），独立判官 agent 以对话原文为基线判色——人指定过的照做（⚪灰，只进日志不打扰）、agent 自己拍板的浮出（🔵蓝，不拦、可翻案）、验证通过的转（🟢绿）、出问题的转（🔴红：报错类自修 3 次不行升级阻塞求助，约束冲突类立刻阻塞）。人翻案时点判官代拟的选项或打一句话，约束只向前生效、不回滚已完成工作。会话结束自动生成报告："agent 做了 N 个决定，你放过 M、翻案 K、其中 X 次纠正方向"——归因人的判断，不归因代码行。
