## 开工第一小时（9/4 晚，两线一起）

1. `npx @deepseek-ai/dsh web` 跑起来，锁版本，配模型（llm-pi-ai 可接赛事提供的任意模型）。
2. 约定并写死两线接口：卡片数据结构（id/类型红蓝/我准备做X/因为Y/你没指定的我选了Z/最可能错在W/备选项）+ 裁决回传（放行/选备选/改写文本/叫停）。
3. Day1 实测（30 分钟）：外部插件包最小 `tools/pre-execute` 监听器装进 dsh → 确认挂起时 loop 真的停、deny 理由模型真的看得见（照 cookbook permission-gate 示例）。

## 插件线任务序列（Host 侧，1 个外部包）

1. 最小拦截：`tools/pre-execute` 拿全参 → 命令行 y/n 当裁决 → `deny(reason)` 回传
2. 卡片抽取：tool 入参 + spec 对照 → 红/蓝判定（红=与 spec 冲突弹出阻断，蓝=spec 没写它自己定的，静默记录不挂起）
3. 裁决执行：放行 / 翻案（deny+理由 或 `agent.inject()` 注入约束，只向前生效）/ `agent.cancel()` 叫停
4. 裁决日志落盘（时间线数据源）；自建超时 `Promise.race`，超时一律 deny（fail-closed）

## 面板线任务序列（Client 侧，1 个 ui 包，抄 `ui-approval` 形态）

1. 卡片面板骨架（mock 数据）：Slots 注入 composer/侧栏，红卡阻断态 + 蓝卡列表
2. 审批交互：备选项点选 + 自由改写 + 叫停按钮
3. 接真数据：复用已桥接的 `user-questions/request` waterfall，或 `ctx.webServer.register()` 自建路由
4. 时间线回放面板

## 砍单规则（落后时按序执行，谁在场谁拍板）

1. 时间线回放 → 降级为静态决策列表
2. 紧急叫停 → 功能保留但不进 demo 动线
3. spec 确认交互 → 简化为粘贴一段文本
4. 面板线整线受阻 → 降级为独立小 Web 页（插件 POST 出来），dsh 只当引擎
5. **永不砍**：红卡阻断 + 翻案只向前生效（核心差异点，砍了作品就没了）
