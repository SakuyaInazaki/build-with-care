# 模型配置：DeepSeek 与自定义服务

日期：2026-09-05。

## 用户授权

用户要求模型配置提供两种方式：DeepSeek 仅输入 API key 并点选模型；其他模型保留接口地址、模型名称等字段。界面需使用正式名称，不能使用“接 ds”“接其他”。

## 展示与配置调整

- 设置页采用“DeepSeek”“自定义服务”两个入口。DeepSeek 页共用一份 API 密钥，分别点选执行模型与审查模型；不会合并两者的上下文或职责。
- DeepSeek 自动填写官方接口地址和来源。预置稳定文本模型 DeepSeek V4 Flash / DeepSeek V4 Pro，默认 Flash；不开放本产品尚无输入能力的视觉实验模型入口。
- 自定义服务继续使用 OpenAI-compatible Chat Completions 字段，保留不同执行／审查服务组合。切换入口不把一个服务的密钥复制到另一个服务的输入框。
- 等待时限收进“等待设置”，保留冻结默认值与原有范围。保存与测试连接仍是不同动作；保存不发起模型请求，未保存的配置不能以旧连接测试结果冒充新配置成功。
- 公共设置仅新增“两个 DeepSeek 角色是否共享已保存密钥”的布尔标记，不返回密钥。更换自定义端点仍不会沿用旧端点的密钥；仅 DeepSeek 官方的等价 URL 形式允许保留同一凭据。
- 默认配置支持一个 `DEEPSEEK_API_KEY` 环境变量；角色专用环境变量仍优先。共享 DeepSeek 密钥不会回退到非官方自定义端点。

## 核对依据与必要兼容修复

- 本机 `@deepseek-ai/dsh-llm` README 展示官方适配器用 API key 环境变量和模型选择即可接入；当前项目使用的是自己的 Chat Completions 兼容适配器，不把改 UI 宣称为替换了 dsh 运行时。
- 2026-09-05 核对 https://api-docs.deepseek.com/ 与 https://api-docs.deepseek.com/quick_start/pricing/：现用稳定文本模型为 `deepseek-v4-flash` / `deepseek-v4-pro`。旧默认 `deepseek-chat` 不再作为新配置默认值；已有明确自定义配置不自动迁移。
- 官方 https://api-docs.deepseek.com/guides/thinking_mode/ 要求工具调用后完整回传 `reasoning_content`。当前适配器丢弃该字段，需要补齐 dsh reasoning block 的返回和后续请求转换，以免新的官方模型选项在第二次工具请求时报 400。不通过关闭思考模式绕开此兼容要求。

以上属于用户授权的配置简化及使其可用所必需的协议修复，不改变执行门禁、Grill 上下文隔离、人工动作或绿色证据规则。实施后的检查结果在此追加。


## 验证结果

- 前端生产构建、5 项前端测试、后端类型检查及全部 27 项后端测试通过。
- 新增 4 项配置测试覆盖共享环境变量、角色专用优先级、官方地址识别、等价地址保留密钥、不同服务清除旧密钥及不同密钥不会被误报为共享。
- 现有真实 dsh + 本机假上游集成测试加入严格协议检查：后续请求缺少 `reasoning_content` 会返回 400；现已验证三次历史工具调用的对应字段完整回传。
- 在独立本机验收服务中通过浏览器实际保存一份测试密钥和不同角色模型、留空保留后改选模型、自定义字段保存。公开响应确认共享密钥状态与模型选择正确；未向外部模型服务发送测试密钥。
- 保存前旧配置的连接测试在改选模型后禁用；保存后恢复可用。前端保存仅返回公开标记，不回显 API 密钥。
- 桌面与 400px 窄屏均完成浏览器检查：窄屏改为单列、页面无横向溢出、弹窗四角保持圆角，浏览器无错误日志。4322 预览已更新；独立验收服务已停止。
