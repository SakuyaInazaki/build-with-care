# Grill 批量问题界面

## 最终语义

- 支持 `grill-batch-v1` 的服务一次返回三道互相独立的问题；新任务分两批，共六问。
- 每题选项都是复选框，也可填写该题自己的补充回答。不同题的选择和输入互不覆盖。
- 每批统一提交。未勾选且未填写的题仍提交空 `choices` 与空 `answer`，表示暂未回答，不生成默认要求。
- 第一批提交后仍进入第二批。第二批结束后，服务才进入最终确认；仍关键但未回答的内容显示在“仍未决定的事项”，明确处理前不能开始执行。
- 第一批提交按钮是“继续”，最后一批是“查看需求”，与最终“确认要求，开始执行”保持区分。
- 服务未声明 `grill-batch-v1` 时，界面继续读取旧 `question` 并发送旧 `{ round, answer }` 请求，兼容已保存的单题会话。
- 页面不展示题数预算或交互实现说明。

## 前端实现

- `App` 根据 bootstrap capability 开启批量表单。
- `Intake` 优先读取 `grill.questions`，按题目 ID 保存复选项和补充内容，发送一组 `answers[]`。
- 请求成功后清空本批本地输入；失败时保留所有勾选和补充回答。请求处理中禁用全部输入和提交按钮。
- 服务已暂存 `pendingAnswers` 时，刷新会按题目恢复选择与补充内容。未编辑的重试只发送 `round`，避免把暂存答案覆盖为空；用户修改后才发送完整批次。
- 宽屏为三列问题卡；1120px 及以下纵向排列。

## 验证证据

- `npm --prefix frontend test -- --run`：3 个现有测试文件，14/14 通过。
- `npm --prefix frontend run build`：TypeScript 与 Vite 生产构建通过。
- `node frontend/tests/intake.browser.mjs`：现有旧单题兼容、多选、自由回答、失败重试保留和时间线回归通过。
- 一次性隔离浏览器夹具验证了：桌面三列；第一批部分多选、自由补充与空题同时提交；503 后内容保留；请求中提交锁定且仅发出一个请求；第二批三题全部留空仍完成该批；最终未决事项出现且开始按钮禁用；390px 卡片纵排且无横向溢出。
- 第二个一次性夹具验证了：`pendingAnswers` 首次与 reload 后均准确恢复；未改动重试请求体只有 `round`；编辑一题后完整三题值准确；兼容会话的两题批次自然显示；最后批按钮为“查看需求”。
