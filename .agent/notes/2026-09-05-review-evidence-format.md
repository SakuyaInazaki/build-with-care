# 审查 evidence 数组兼容与暂停动作恢复

用户在测试时报告审查模型将 evidence 返回为数组，旧 schema 仅接受字符串，导致整份 Zod 错误展示在决策看板。

- 审查证据兼容字符串和字符串数组；数组逐项以换行拼接，保留全部内容，不截断，不改变分类、引用或证据含义。提示词补全字段类型。
- 其他无法安全规范化的字段类型仍拒绝解析；错误展示中文字段名称和重试入口，不将 Zod issues 原文显示到页面。不将格式失败改成业务冲突或自动放行。冲突仍须有有效的现行约束引用和非空证据。
- 看板统一显示“审查需要重试”，避免将格式问题误称为连接故障。
- 为更新当前已暂停的服务而不丢弃拟写入代码，新增跨进程恢复：用户明确继续时，如果最后一个动作是因 review.failed 暂停、从未释放的 write_file / edit_file，可使用原 stepId、callId 和完整参数，先通过 dsh 工具运行时重新审查当前约束，再继续执行模型。其他调用及已执行动作不按此路径重放。
- 恢复仍经过完整 pre-execute、审查、门禁及工具执行流程；冲突必须待人处理。审查完成前不新增执行模型请求。更新服务时不修改要求或现有成果，密钥与推理强度保留。

此恢复能力替代此前“任何服务重启都从执行模型重开”的局限；不等于跳过审查释放旧调用。原始工程说明只保存在本笔记，不注入用户需求。

验证覆盖：字符串与多条长证据保真、缺少证据/无效引用拒绝、错误内容不泄露 schema 明细、暂停动作跨重启恢复保持身份和参数、恢复冲突仍进入人工门禁、原动作完成后才请求执行模型。

上线验证：在原调用因格式错误暂停、无在途模型请求时更新服务，恢复原 write_file；stepId、callId、完整参数、15 条要求及 v2 版本保持不变，设置文件校验值未变。真实独立审查已成功返回带三条证据的冲突结果，进入人工门禁。随后页面显示该动作“仅本次允许 / 已执行”，任务继续流式推进；本次修复操作没有代替用户点击放行。后端全量 46 项、前端 8 项测试通过，恢复冲突门禁的加强测试及类型检查通过，生产构建完成。
