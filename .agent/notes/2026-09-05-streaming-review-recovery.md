# 流式接入与审查恢复修复

用户在定位后明确要求立即修复。该笔记记录本次相对冻结需求及先前故障处理补丁的语义变化。

- 执行与审查使用真正的 Chat Completions SSE；流式块实时交给 dsh，保留完整推理以满足后续工具对话协议。保留用户选择的推理强度，不添加执行总时限或隐式 token 上限；用户停止仍立即取消网络请求。自定义服务若忽略 stream 并返回 JSON，兼容读取完整响应。
- 中断、格式不完整、上游截断的工具参数不执行。模型生成状态展示连接、思考、生成及实际已接收字符数；不展示虚构百分比。
- **审查等待 8 秒改为慢响应提示阈值，不再是取消模型请求的硬截止。** 原动作继续保持未执行，直到审查成功。模型真正返回业务冲突或不确定结论时才进入人的判断。这个变化替代冻结需求中审查等待的原先硬截止实现；默认数值仍为 8 秒，设置标签改为“审查耗时提示（秒）”。人工审批默认十分钟及其到期行为不变。
- 审查连接、格式等技术错误保留正在等待的工具调用，提供独立“重试审查”，重试相同参数并重新核对当前约束；不重跑执行模型、不新增人类需求、不改变约束版本、不生成虚假的人工判断卡。重试可使用用户更新后的审查连接配置。停止或服务关闭仍取消等待；服务重启后不直接放行旧调用。
- 这替代同日 `2026-09-05-review-service-failure.md` 中“技术审查失败结束整轮”的临时方案，解决重试还要从执行模型重新生成的问题。
- 执行提示明确先读取文件、按可检查的小目标推进，避免在必要读取前先草拟整个应用；不修改用户的业务要求。该提示不保证最高推理模式的每次响应都很短。
- 新增模型响应耗时与用量记录，原始事件保留。没有保存的历史网络阶段信息不补造。
