# 任务归档界面语义

日期：2026-09-06

## 用户路径

- 支持归档能力的后端通过 bootstrap 返回 `capabilities: ['task-archive-v1']`；旧进程没有能力标记时，界面不显示归档入口，也不会调用不存在的接口。
- 默认任务概览和侧栏“最近任务”排除带 `archivedAt` 的任务。侧栏提供独立、带数量的“已归档”入口；归档列表为空时显示明确空状态。
- 空闲的待确认任务，以及已完成、出错、已停止或已中断的任务，在任务标题旁显示可用的“归档任务”。需求是否已经确认不阻止归档；归档保留原 Grill、状态和 revision。归档后保持当前任务打开，并显示“已归档”和“恢复任务”；返回时进入归档列表。
- 运行中、等待决定或正在停止的任务也显示“归档任务”，但按钮禁用，并明确提示“请先停止任务，再归档”。
- 恢复使用同一任务 ID 和原状态，不新建任务、不改变要求版本。恢复后返回普通任务概览。

## 归档只读范围

- 归档是组织元数据，不改变决策看板的卡片分栏、验证证据和人的处理状态。
- 归档任务仍可查看决策看板、成果预览与源码、过程时间线、原始记录、判断记录和导出。
- 归档期间不显示继续、停止、重试审查、重新检查文件、补充要求、需求确认、纠正/放行或保存复盘等执行和修改入口。
- 物理删除沿用原有显式输入确认流程；这是已约定保留的独立永久删除语义。
- 页内提醒和桌面通知均忽略归档任务；归档的 error/interrupted 状态也不触发自动跳过欢迎页。

## 兼容与验证

- v3 及以后继续显示文件重新检查，并保留旧 30 次限制错误的迁移提示；归档入口只依赖 `task-archive-v1` 能力，不依赖精确版本字符串。
- 未新增测试文件或测试用例。最终前端现有测试 14/14、TypeScript/生产构建和 `git diff --check` 通过。
- 临时隔离浏览器夹具覆盖默认过滤、归档数量、归档/恢复、刷新后状态、归档任务完整只读导航、成果脚本/源码、复盘锁定、旧后端能力隐藏和 390 px 无横向溢出；夹具没有写入仓库。
- 追加夹具实际归档并恢复 `ready(confirm)`，确认 status、Grill 与 revision 不变；运行态归档按钮可见、禁用且有停止提示。
- 对真实完成态只读复制加入 `archivedAt` 前后复算，37 张卡及分栏完全一致：需要判断 0、正在推进 0、等待验证 8、已验证 18、已停止与已拦停 11。真实任务本身未归档、未恢复、未修改。
