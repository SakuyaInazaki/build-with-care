# 文件编辑参数错误与审查失败分离

用户报告 v3、16 条要求的任务停在“审查需要重试”，错误为“替换目标不是文件中唯一的匹配文本”。核对实际文件，oldText 匹配次数为 0，并非出现多次。

根因：edit_file 生成供审查使用的候选全文时，读取文件和精确匹配校验被包在审查模型异常的 catch 中。本地参数错误因此进入等待人工重试审查的状态，而重复审查不会改变错误参数。

- 将编辑预校验移到审查请求之前。读取失败、空 oldText、零匹配或多匹配通过 dsh 工具错误结果返回执行模型，由模型读取最新文件并修正参数；不创建审查重试横幅、业务决策卡或人工门禁。
- 错误明确提供实际匹配次数和修正方式。不做模糊替换、不替换所有匹配、不擅自选取第一处。文件在无效调用时不改变；有效修改仍须审查通过。
- 保留普通工具错误连续 3 次后的既有失败收敛机制。此次修复落实冻结需求第 5 节的普通运行错误恢复行为，不增加用户需求。
- 审查预览与实际执行共用精确替换函数，newText 按字面写入，避免 JavaScript replace 将 `$&`、`$$` 等当作替换指令，确保模型提交内容与实际写入一致。
- 旧进程已暂停的错误调用在显式恢复时仍保留原身份和参数，先进行预校验；无效调用返回错误给执行模型，不再进入审查重试。恢复消息按实际工具结果表述，不声称无效动作已完成审查。

验证覆盖零匹配、多匹配、空文本、文件不存在的完整模型/工具往返：原文件保持不变，错误进入下一次模型上下文，重新读取并修正后的有效修改正常审查和执行。覆盖恢复期间文件变化导致原编辑失效的情形，以及替换内容中特殊字符的字面保真。

验证结果：类型检查通过；后端 51 项测试全部通过，其中需要监听本机端口的 11 项在允许本机网络后复跑通过（首次受沙箱 EPERM 阻止）。2026-09-05 20:38 更新暂停中的生产服务，原编辑调用以工具错误结束并进入执行模型上下文，未执行无效修改。核对要求、版本、文件哈希与设置文件哈希保持不变。页面已恢复实时同步，显示“正在推进 / 正在思考”，接收到实际流式字符，不再显示审查重试横幅。
