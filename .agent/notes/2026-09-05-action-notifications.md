# 待用户操作提醒

用户要求在挂机、切换应用时得知需要处理的事项。本次新增通知，不更改任何放行/验证/恢复语义。

- 触发：有效待判断门禁、审查技术失败需重试、执行错误或中断、待回答澄清及最终确认。普通执行/慢审查、等待验证、单纯未审阅蓝卡和主动停止不触发。
- 页面内持续显示待处理浮层与前往任务按钮，页签标题显示数量；不抢焦点、不自动打开审批对话框、更不替人认可。
- 顶栏“开启桌面提醒”由用户点击后申请浏览器通知权限。离开页面焦点且已授权时发系统通知，点击尝试唤回页面并选择对应任务；已处理事项不再跳转。关闭提醒及已通知事项标识存于本机浏览器，同一标识的状态重发或刷新不重复发通知。通知只包含任务短标题和操作类别，不发送原始诊断、模型输入或密钥。
- 切到概览或其他任务时，为仍活动的任务保留后台 SSE 订阅；只读接收，不增加模型调用。
- 本实现依赖网页保持打开及本机服务在线。浏览器/系统权限或专注模式可能影响系统通知呈现，失败时仍保留页面提醒；不声称浏览器关闭后具备推送能力。依据 MDN Notifications API：权限必须由用户手势申请，桌面 Notification API 可在页面后台显示通知。
- 仅前端更新，不重启当前执行服务。

验证：前端 13 项回归和类型检查/生产构建通过。`node frontend/tests/notifications.browser.mjs` 使用隔离 Chrome、模拟 SSE 与 Notification API，验证只在点击后申请授权、概览仍订阅活动任务、前台浮层、后台通知、重复事件去重、点击返回、处理后关闭、关闭偏好/刷新保留，以及拒绝权限时页面回退。未代替用户申请真实通知权限，也未将模拟接口测试说成系统通知实测。

授权依据：https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API

## 已有提醒不能关闭的修复

用户明确指的是已弹出的通知，不能将此问题误解成开启或关闭桌面通知权限。根因是页面待处理浮层没有关闭入口。

- 为已有浮层增加独立的右上角 ×，可访问名称“关闭这条提醒”。按事项标识关闭，关闭记录存于 sessionStorage；当前标签页刷新、重复 SSE 状态不会再弹同一事项。
- 如该事项还关联着本页发出的系统通知，同步 close；不修改浏览器权限、任务状态、门禁决定或审阅结果。标题仍显示实际待处理数量，真正的新事项仍可提醒。
- 生产构建已完成并在现有 4322 页面重新加载。加载后真实任务已处于 running，原中断提醒因此自然消失；没有伪称实际点击了那条已经消失的提醒。未重启服务或停止任务。
- 隔离 Chrome 回归实际点击关闭按钮，验证浮层消失、重复状态不重弹、刷新保留关闭、新事项仍出现、关闭不改变待处理计数。Notification 为模拟接口，不等同真实系统通知实测。类型检查通过，当前后端 62 项、前端 14 项测试通过。
