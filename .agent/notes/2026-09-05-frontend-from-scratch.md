# 从零新建前端：授权、范围与变更记录

日期：2026-09-05。

## 用户确认

- 用户明确要求全部推翻现有前端，按 Apple Design 和本机 Refactoring UI 重新构建。
- 用户进一步澄清：“从 0 开始构建，不是在原来的基础上弄”。因此新建独立 `frontend/` 工程，从空白文件实现，不复用旧 App、CSS、页面布局或组件。
- 用户要求任何新增需求、破坏性调整或语义变化必须写入 `.agent/notes/`。

## 权威基线

`docs/requirements-v1-frozen.md` 继续作为唯一首版实现语义与验收基线。本次用户授权的是前端从零重建，不是解除冻结或扩展产品范围。Apple Design / Refactoring UI 的一般建议不能覆盖冻结行为。

## 本次范围（实施中）

1. 新建 `frontend/`：独立包、构建配置、入口、组件、样式和测试。保留旧前端文件作为历史实现，新的产品入口指向新工程。
2. 新建需求澄清／最终确认、状态看板、非模态双栏卡片详情、成果与验证、过程记录、判断复盘、模型设置。
3. 复用 `decision-desk/server` 的后端接口和共享数据契约作为数据接入基础；不复制旧前端。
4. 仅对新前端必需且冻结文件已规定的行为补接口：多轮 Grill 与最终确认门禁、红卡四动作映射、相同模型配置、两个等待时限、任务物理删除与独立删除审计。
5. 默认任务入口使用真实模式，不把旧固定脚本作为正式演示；已有开发测试记录始终明确标识。

## 入口与破坏性调整的处理

- 新工程将成为本次交付的前端；这是用户明确授权的产品界面替换。
- 不删除用户既有任务、模型配置、旧前端文件、历史需求和旧 note；不修改冻结文件。
- 正常合规写入继续自动执行。人工认可不产生绿色证据；不新增回滚、多 Agent、模型来源必须不同等行为。
- 数据删除功能是冻结要求；必须实际删除指定任务的数据并留下独立审计，不能用隐藏列表项冒充删除。活动任务不可直接删除。

## 验证与剩余边界

实施后追加实际文件、检查结果和未完成的后端冻结能力。前端完成不等于 24 项正式验收或 3 次真实模型闭环完成。


## 实际入口变更

根目录 `dev` / `build` / `start` 已切换到独立 `frontend/`；原命令保存在 `*:legacy`。新工程的开发服务通过 `FRONTEND_ROOT` 指定新 Vite 根目录，生产通过 `FRONTEND_DIST` 指向新产物。默认新数据目录为 `frontend/.data/runs/`，不删除、不自动迁移旧任务。

后端补充文件：`server/grill.ts`，以及 `manager.ts`、`app.ts`、`store.ts`、`index.ts` 和共享类型。原前端的 `decision-desk/src/`、根 `src/public/` 未修改。

已通过前端构建、5 项前端状态／证据测试、后端类型检查及全部 23 项后端测试（含 4 项新测试）。独立浏览器验收使用临时数据，不构成冻结验收通过；剩余后端边界记录于 `frontend/README.md`。
