# 合并后端：执行记录与验收状态

用户明确要求：“赶紧合并两套后端，再去核实一下还有什么功能没实现却谎称实现的。”本记录承接该授权；当前冻结需求及后续已确认改动继续生效。

## 合并方向

- `decision-desk/server/` 为当前产品唯一运行后端，保留 `/api/runs` 与用户已有 RunState/Step/Gate/Intervention 数据。
- 将旧 `src/work-unit.ts` 的结构化声明、约束匹配机制及旧 runner 的 begin_unit/end_unit 契约合并到当前 dsh 运行链。工作单元必须可观察、可校验，有明确开始、关闭和隔离上下文。
- 不复用旧 LlmJudge 的错误回退放行、审查输入截断，以及公开回滚分支语义。保留当前流式协议、精确调用例外、停止收敛和已确认的恢复操作。
- 合并期间逐步消除两份有效服务入口；历史模块和历史数据的处理必须明确记录，不将接口重命名等同于能力迁移。
- 完成后逐项核实旧交付声明、当前代码、测试证据与实际运行服务，未实现或未上线的功能明确列出。回归测试数不代表冻结评测通过数。
