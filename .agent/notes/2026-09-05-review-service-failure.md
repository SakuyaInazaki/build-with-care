# 审查服务故障与人的判断分离

日期：2026-09-05。

用户报告审查超时被展示为“需要你判断 / 这一步需要人工核对”，且无法处理。根因是执行前审查的 catch 分支把网络、超时、格式错误等系统故障合成为 uncertain Review，随后创建人工门禁。这不能让人判断真实的业务取舍。

本次在用户要求下改为：技术审查失败记录 review.failed，结束本轮为 error，不产生人工决策或人工门禁，拟执行动作不放行；保留完整拟执行参数与事件，用户可通过现有独立“继续任务”入口重试本轮。它不新增要求，也不假装重用了已丢失的模型调用。真正由审查模型返回的业务 uncertain 仍保留人工核对流程。

执行模型请求没有固定总时限的设置不变。审查独立等待默认 8 秒及其可配置范围保持冻结要求；发生该超时只标为技术审查失败，错误显示中文。旧记录中 source=system 且 topic=review-failure 的卡片以技术故障展示在结束记录中，不再放入人的判断栏或显示“未审阅”。

当前测试任务已停止；更新后台前再次验证无活动任务，保留持久化密钥、推理强度及已有记录，不自动开始新的模型请求。

后续用户要求立即修复，最终实施改为真正流式、慢审查继续等待及原动作重试；本笔记的“失败结束整轮”和“8 秒取消请求”方案已被 `2026-09-05-streaming-review-recovery.md` 替代。
