# 只读工作单元的看板展示

日期：2026-09-06

## 问题

没有决策、只执行 `list_files` / `read_file` 的工作单元完成后不会产生需要验证的产物。此前看板仍把这类单元放进“等待验证”，但它们没有 artifact hash，也没有合理的后续验证动作，因此会永久停留并误导用户。

## 展示语义

- 已完成、没有决策、且只包含 `begin_unit`、`end_unit`、`list_files`、`read_file` 的工作单元不生成决策看板卡片。
- 原始工作单元、步骤和事件不删除、不改写，仍完整保留在过程时间线及原始记录。
- 只要单元包含决策、写入、命令产物、显式验证、失败或未完成状态，仍按原规则生成卡片。
- 不把只读完成伪造成绿色受控验证，也不放进“已停止与已拦停”。

同批兼容修复还让完成的 `verify_app`-only 单元读取其实际验证路径，并让 `run_command` 单元读取后端持久化的 `artifactPaths`。二者仍必须满足当前文件 hash、要求 revision、完成的受控 `verify_app` 步骤及真实通过结果，才进入“已验证”。

## 验证

没有新增测试文件或测试用例。使用临时命令构造三种状态进行检查：只读完成单元不出现在 `boardItems()`，但仍存在原 `RunState.workUnits`；verify-only 与命令产物单元均只在绑定当前受控检查证据时进入“已验证”。临时脚本未保存。
